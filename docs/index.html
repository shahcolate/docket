The permission layer — and the paper trail — for AI agents.

Agents don’t just answer anymore. They send the email, move the meeting, file the ticket. Docket makes them check a one-page rule file before they act — allow, ask, or deny — and leave a tamper-evident record after. Anything you didn’t write down, the agent must ask about.

I.Two readers, one page

If you run the business

  • Agent autonomy becomes governed. What each agent may do is written, versioned, and reviewable — not buried in a prompt.
  • Every action is auditable. A tamper-evident record of what the agent saw, did, and where it stopped. Hand it to a client or a compliance review.
  • No vendor lock-in. The rules and the record are plain files in your repo. Switch AI vendors without losing either.

If you build the product

  • A file format, not a platform. One Markdown file per recurring task. Deterministic allow/ask/deny verdicts with exit codes 0/2/3 — gate hooks and CI on them.
  • Hash-chained JSONL record. docket record verify catches any edit, deletion, or reordering.
  • Works where agents work. Compiles to CLAUDE.md, AGENTS.md, Cursor rules; ships an MCP server. Zero dependencies, node ≥ 18.

II.One loop, five layers

Don’t configure an assistant. Bound one recurring task — the insurance appeal, the client follow-up, the weekly plan — with five layers the agent must obey.

Brief
Everything that must be true in the agent’s head before it starts — the context that changes the answer.
Procedure
How this job is done properly: which sources count, what finished looks like, the known ways it goes wrong.
Warrant
What it may read / draft / change / send on its own, and what always needs approval. No warrant, no action.
Record
Verifiable evidence of what it saw, did, skipped, and where it stopped — hash-chained, so history can’t be quietly rewritten.
Reserved
The calls that stay human: accounts, secrets, spending, final sign-off.

III.On the record, not on trust

Every warrant check and every piece of finished work is appended to a hash-chained log. Try to falsify it: edit the underlined words in entry № 2, then verify.

IV.Findings

42 scenarios modeled on real agent-overreach incidents — unauthorized emails, calendar “tidying”, invented commitments, agents widening their own permissions — run against the shipped templates on every build.

Matching is asymmetric by construction: a phrasing difference can cause an unnecessary ask — never an accidental allow. The numbers regenerate with npm run eval; the invariant fails the build if it breaks.

V.Your rules, every model

Loops are the source of truth; assistant files are build artifacts. One compile puts the same rules in front of every tool, and docket mcp lets agents check warrants and write the record natively.
